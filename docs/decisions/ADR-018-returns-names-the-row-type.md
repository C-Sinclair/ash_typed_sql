# ADR-018 — `returns` names the element type, and `get?` decides list or one

**Status:** accepted
**Date:** 2026-10-21
**Last changed:** 2026-10-21
**Deciders:** Conor Sinclair
**Relates to:** [DD-002](../designs/DD-002-query-actions.md), `AshTypedSql.Returns`, `AshTypedSql.Transformers.GenerateQueries`, `Mix.Tasks.AshTypedSql.Gen.Query`, `Mix.Tasks.AshTypedSql.Gen.Returns`

## The decision

A `query` takes one `returns` option naming an `Ash.TypedStruct` module, which is the element type of the action's result. `get? true` makes the action return one element with `allow_nil? true`, and otherwise it returns `{:array, module}`. Without `returns`, the action keeps the generated `<Query>Row` type. Compilation checks the module's fields against the snapshot columns by name, Postgres storage type and nullability, and refuses `returns` together with `as`. When the module does not exist, `mix ash_typed_sql.gen.query --returns` and `mix ash_typed_sql.gen.returns` write it from the snapshot. There is no `row_type` option.

## Context

The generated `<Query>Row` module is named after the resource and the query, so two queries that return the same columns get two types. A client generated by `ash_typescript` then shows two names for one shape. Users also want the row type in their own namespace, with a `@moduledoc` and functions of their own, which a module created inside a transformer cannot hold.

## Options considered

### Option A — `returns Module`, list or one decided by `get?`

One key names the element type. `get?` already decides list or one for the generated row, so the two options stay independent. Costs a check at compile time that the module matches the snapshot.

### Option B — `row_type Module` plus `returns {:array, Module}`

Mirrors Ash's own `returns` on generic actions. Costs two ways to say the same thing, and a `returns` that can disagree with `get?`.

### Option C — keep generated rows only, and let users alias them

No new option. The generated name stays tied to the resource and the query, and the module cannot carry user code.

## Decision and why

Option A. A single key cannot disagree with `get?`, and the existing `get?` behaviour in `AshTypedSql.Run` stays the same. The field check reuses `AshTypedSql.Argument.storage/2` from [ADR-011](ADR-011-query-arguments-are-ash-arguments-mapped-by-position.md), so a field may narrow a column the same way an argument narrows a parameter. Writing the module is a generator's job rather than the compiler's, because compilation must not write source files.

## Consequences

- **What it rules out.** A `returns` on `as` queries, which return resource records. A `returns` module that is defined later in the same compile than its resource and refers to the resource's generated enum modules.
- **What it makes worse.** The module and the SQL can drift. Compilation refuses the drift, and `mix ash_typed_sql.gen.returns` rewrites the fields.
- **What stays open.** Whether `returns` should accept an `Ash.Type.NewType` over `:map` with `fields`.
- **What now depends on it.** `AshTypedSql.Returns.check/4`, the `--returns` option of `mix ash_typed_sql.gen.query`, and `mix ash_typed_sql.gen.returns`.

## Evidence

- `test/ash_typed_sql/returns_test.exs`: "casts each row through the returns module", "refuses a field Postgres stores differently", "refuses allow_nil?: false on a nullable column", "refuses returns together with as", "is skipped when the query has no snapshot".
- `test/mix/tasks/gen_test.exs`: "writes a missing returns module from the snapshot, and adds returns", "rewrites the fields of an existing returns module and keeps the rest".

## Notes

The generator writes enum columns as `:atom` with `one_of` constraints, not as the enum module the resource generates. The resource compiles after its `returns` module, so the module cannot name a type the resource defines. A missing `returns` module is always a compile error. `mix ash_typed_sql.gen.returns` does not compile the resource. It finds the `query` in the resource's source with Igniter, reads the query's snapshot from disk, and writes the module from the snapshot columns. When the query has no `returns`, the task adds one, naming `--returns` or `<Resource>.<QueryName>`. `mix ash_typed_sql.gen.query --returns` composes `gen.returns`, which reads the snapshot that `gen.query` added to the same change set.
